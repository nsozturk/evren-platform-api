evren-platform-api Documentation

evren-platform-api is a free, open-source, unofficial guide and toolkit for the EVREN AI platform's REST API that shows how to create datasets, upload files resumably and publish them, with a ready OpenCode workflow.

Unofficial. This project is not affiliated with or endorsed by SSB or the EVREN platform. "EVREN" is used only to say which API the code works with. No EVREN logo, colours or branding are used. You act under your own account and under the platform's terms; uploaded datasets and models may be used by the platform for training under its user agreement, so read that agreement before you upload.

Resumable uploads

Journal, retry with backoff, SHA-256 dedup. Stop and re-run at any point.

NLP via the API

The web form offers only vision and medical, but the API accepts NLP.

Verify by hash

Compare the server's file list with your local manifest, SHA-256 for SHA-256.

Stdlib only

Python 3.9+ and nothing to install. Tests run offline.

OpenCode ready

AGENTS.md contract plus the /evren-publish-dataset command.

Measured, not guessed

Facts were checked against the live API on 2026-10-26 and marked verified or documented.

Why this exists

Community projects already cover EVREN's LLM gateway: an OpenCode provider installer, command-line clients, chat UIs, and an MCP server for training. What nobody had written down is the Platform REST API for datasets:

  • which API key type can call which endpoint,
  • that an NLP dataset can be created through the API even though the web form only offers vision and medical,
  • the three-step upload (presign, PUT, confirm), how deduplication works, and how to verify the result,
  • how to do all of it resumably, from a script or from an AI coding agent.

This repository documents those facts as they were measured against the live API on 2026-10-26, and ships one small tool that does the work.

Quick Start

You need Python 3.9 or newer. There is nothing to install.

1. Get a key

In the EVREN web app open Settings -> API Keys and create an evren_plt_ key (it is shown once).

git clone https://github.com/nsozturk/evren-platform-api
cd evren-platform-api
export EVREN_PLATFORM_KEY="evren_plt_..."     # your own key; never commit it

2. Prepare a dataset folder

Put your data files, a dataset card and a README in one folder:

mkdir my-dataset                               # put train.parquet, data.jsonl, ... in it
cp examples/card.example.json my-dataset/card.json   # edit name, description, license, tags
$EDITOR my-dataset/README.md                   # the dataset card shown on the platform

3. Create the dataset (private NLP; preview first)

python3 tools/evren_dataset_upload.py manifest my-dataset
python3 tools/evren_dataset_upload.py create --card my-dataset/card.json --readme my-dataset/README.md --dry-run
python3 tools/evren_dataset_upload.py create --card my-dataset/card.json --readme my-dataset/README.md --visibility private

4. Upload

Safe to stop and re-run at any point; it resumes.

python3 tools/evren_dataset_upload.py upload my-dataset

5. Verify

Check that every file is on the server with a matching SHA-256:

python3 tools/evren_dataset_upload.py verify my-dataset
# verify my-dataset: server 9 / manifest 9 | missing [] | extra [] | not ready [] -> OK

The upload tool

tools/evren_dataset_upload.py has four subcommands: manifest, create, upload and verify. It prints timestamped progress lines, retries on 5xx, 429 and network errors with backoff, streams files from disk instead of loading them into memory, and keeps a journal so a re-run skips finished files.

Defaults live inside the dataset folder: .evren_dataset.json, .evren_upload_journal.jsonl and .evren_upload.log.

Exit codeMeaning
0Success.
1The operation failed: a file failed to upload, verify found a mismatch, or the API returned an error.
2Usage or configuration error, such as a missing EVREN_PLATFORM_KEY or a missing manifest.

API keys and authentication

EVREN exposes two separate HTTP surfaces. They use different hosts, different headers and different key types. Mixing them up is the most common cause of 401 and 403 errors (see Errors).

SurfaceBase URLAuth headerKey prefix
Platform REST API (datasets, models, billing, catalogue)https://api.ssyz.org.tr/api/v1X-API-Key: <key>evren_plt_ (full access), evren_mdl_ (models and inference only)
LLM gateway (chat, embeddings, OCR, ...)https://evren-llmapi.ssyz.org.tr/v1Authorization: Bearer <key> (X-API-Key is also accepted)evren_llm_

For evren_ keys the Platform API rejects Authorization: Bearer with a 401. Always send X-API-Key there.

Creating a key

Keys are created in the EVREN web app under Settings -> API Keys (/api-keys on https://evren.ssyz.org.tr). The full key is shown once; copy it when it appears.

  • Creating, listing or uploading datasets: evren_plt_.
  • Only running models / inference: evren_mdl_.
  • Only calling the LLM gateway: evren_llm_.

What each key can call

Measured against the live API on 2026-10-26:

KeyGET /auth/meGET /datasetsGET /modelsLLM gateway GET /v1/models
evren_plt_200200200401
evren_mdl_403 "only inference and model endpoints"403200401
evren_llm_401401401200 after the terms are accepted, otherwise 403 terms_not_accepted

So dataset work needs an evren_plt_ key, and an LLM-gateway key cannot touch the Platform API at all.

Keeping the key out of your repo

This toolkit reads the Platform key from one environment variable:

export EVREN_PLATFORM_KEY="evren_plt_..."   # paste your own key; never commit it

Optional, macOS only: store it in the login Keychain once and load it per command so it never sits in your shell history or dotfiles.

security add-generic-password -s evren-platform-key -a "$USER" -w     # prompts for the value
EVREN_PLATFORM_KEY="$(security find-generic-password -s evren-platform-key -a "$USER" -w)" \
  python3 tools/evren_dataset_upload.py verify ./my-dataset

Smoke test

curl -sS https://api.ssyz.org.tr/api/v1/auth/me -H "X-API-Key: $EVREN_PLATFORM_KEY"
curl -sS https://api.ssyz.org.tr/api/v1/billing/balance -H "X-API-Key: $EVREN_PLATFORM_KEY"

/billing/balance returns {balance, available, held, total_earned, total_spent} in credits (CR).

Response envelope

Most endpoints answer {success, data, message}. Some return the object directly: POST /datasets returns the dataset, GET /datasets returns a bare list and GET /models returns {items, total}. Write client code that tolerates both shapes. The bundled uploader unwraps {success, data} when present.

Datasets

Base URL https://api.ssyz.org.tr/api/v1, header X-API-Key: <evren_plt_ key>.

Create a dataset: POST /datasets (verified)

{
  "name": "my-text-dataset",
  "modality": "NLP",
  "description": "What it contains.",
  "readme": "# My dataset\n\nMarkdown card.",
  "visibility": "private",
  "license": "MIT",
  "tags": ["nlp", "text"]
}
FieldNotes
name, modality, visibilityRequired. modality is one of VISION, AUDIO, NLP, MULTIMODAL, MEDICAL. visibility is public, private or unlisted.
description, readme, licenseOptional.
tagsOptional, at most 10.
contributions_enabled, org_idOptional.
task_profileOptional, used with MEDICAL.

The response is the dataset object itself (not wrapped): id, slug, owner_username, and more. Keep the id; every other call uses it.

NLP datasets work through the API. The web "new dataset" form only enables VISION and MEDICAL, but the API accepts "modality": "NLP". This is the main non-obvious fact this project documents. Start with "visibility": "private" and change it only after you have verified the contents.

Change visibility with PATCH /datasets/{id} and body {"visibility": "public"} (or private / unlisted); it returns 200 with the updated dataset (verified 2026-10-26). The dataset settings page in the web app does the same.

List datasets: GET /datasets (verified)

Query parameters: scope = all, owned or shared (any other value returns VALIDATION_ERROR), plus visibility and modality filters. The response is a bare JSON list.

curl -sS "https://api.ssyz.org.tr/api/v1/datasets?scope=owned&modality=NLP" -H "X-API-Key: $EVREN_PLATFORM_KEY"

Resolve by owner and slug: GET /datasets/{owner}/{slug} (documented)

Useful when you only know the public name.

List items: GET /datasets/{id}/items (verified)

Query: limit (200 at most) and cursor. Response:

{
  "items": [
    {"id": "...", "original_filename": "train-00000.parquet", "file_type": "document",
     "sha256_hash": "...", "status": "ready", "split": "..."}
  ],
  "next_cursor": ""
}

Page until next_cursor is empty. Items carry the SHA-256 you uploaded, so you can verify a dataset against a local manifest by hash; tools/evren_dataset_upload.py verify does exactly that. In practice a .jsonl file becomes file_type: text, a .parquet file becomes file_type: document, and status is ready right after confirmation.

Delete: DELETE /datasets/{id} (verified)

Returns 204. This removes the dataset; treat it as irreversible and only run it on datasets you created for testing.

Search the public catalogue: GET /universe/search (verified)

Query: q, type (dataset or model), modality, limit, offset.

curl -sS "https://api.ssyz.org.tr/api/v1/universe/search?q=cve&type=dataset&limit=5" -H "X-API-Key: $EVREN_PLATFORM_KEY"

Versions and export (documented, not exercised)

CallPurpose
GET /datasets/{id}/versionsList dataset versions.
GET /datasets/{id}/export/formatsExport formats available for the dataset.
GET /datasets/{id}/export/download?format=<fmt>&version_tag=<tag>Download an export. format is YOLO_TXT, COCO_JSON, VOC_XML or CSV.

The annotation formats are aimed at vision datasets. Check export/formats for what a given dataset offers before relying on one.

Uploading files

Uploading is a three-step flow per file: presign, PUT, confirm. A file that is not confirmed is not added to the dataset. All three steps use X-API-Key and the dataset id from Datasets.

What you can upload

GET /datasets/upload/extensions returns {extensions: [...], by_file_type: {image, video, audio, text, ...}}. The accepted list includes .parquet, .arrow, .feather, .sqlite, .db, .csv, .tsv, .json, .jsonl, .ndjson, .txt, .md, .pdf, .tar, .tgz, .tar.gz, common image, audio and video formats, and .dcm. .npy is not accepted. Convert NumPy arrays to Parquet first.

Step 1: presign

POST /datasets/{id}/upload/presign

{"files": [{"filename": "train-00000.parquet", "sha256_hash": "<hex>", "file_size": 82455248}]}

client_uid is an optional extra field on each file entry. Response:

{
  "presigned_urls": [
    {"filename": "train-00000.parquet", "sha256_hash": "<hex>",
     "upload_url": "/datasets/<id>/upload/put?key=<object key>",
     "direct_upload_url": "...", "object_key": "<object key>"}
  ],
  "duplicates": ["<sha256 of files the dataset already has>"]
}
  • upload_url is relative. Prefix it with the API base (https://api.ssyz.org.tr/api/v1).
  • If the dataset already contains a file with the same SHA-256, that hash comes back in duplicates and you skip the file. This makes re-runs cheap and safe.

Step 2: PUT the bytes

PUT <api base><upload_url> with the raw file as the body, headers X-API-Key and Content-Type: application/octet-stream. Response: {"ok": true, "key": "...", "size": N}. Stream the file from disk instead of reading it into memory.

Step 3: confirm

POST /datasets/{id}/upload/confirm

{"items": [{"object_key": "<object key>", "sha256_hash": "<hex>", "filename": "train-00000.parquet", "file_size": 82455248}]}

Returns 201 with {created, ids, actual_count, batch_duplicates}.

Size and sharding

Single files of 0.7 KB, 105 MB and 316 MB all uploaded fine, at roughly 8-11 MB/s from Türkiye. No per-file limit was hit up to 316 MB. This project shards at 280 MB or less so every file stays inside what was actually tested. Split large Parquet or JSONL files into numbered shards (train-00000-of-00009.parquet) before uploading.

Example: curl

A complete single-file script lives in examples/curl-upload.sh. The core calls:

API=https://api.ssyz.org.tr/api/v1
SHA=$(shasum -a 256 train-00000.parquet | cut -d' ' -f1)      # sha256sum on Linux
SIZE=$(wc -c < train-00000.parquet | tr -d ' ')

# 1) presign
curl -sS -X POST "$API/datasets/$DATASET_ID/upload/presign" \
  -H "X-API-Key: $EVREN_PLATFORM_KEY" -H "Content-Type: application/json" \
  -d "{\"files\":[{\"filename\":\"train-00000.parquet\",\"sha256_hash\":\"$SHA\",\"file_size\":$SIZE}]}"

# 2) PUT (use the relative upload_url from step 1; -T streams the file)
curl -sS -T train-00000.parquet "$API<upload_url>" \
  -H "X-API-Key: $EVREN_PLATFORM_KEY" -H "Content-Type: application/octet-stream"

# 3) confirm
curl -sS -X POST "$API/datasets/$DATASET_ID/upload/confirm" \
  -H "X-API-Key: $EVREN_PLATFORM_KEY" -H "Content-Type: application/json" \
  -d "{\"items\":[{\"object_key\":\"<object_key>\",\"sha256_hash\":\"$SHA\",\"filename\":\"train-00000.parquet\",\"file_size\":$SIZE}]}"

Example: Python standard library

import hashlib, json, os, urllib.request

API = "https://api.ssyz.org.tr/api/v1"
KEY = os.environ["EVREN_PLATFORM_KEY"]


def call(method, path, body=None, stream=None, size=None):
    headers = {"X-API-Key": KEY}
    data = None
    if stream is not None:                      # open file object: streamed, not read into memory
        data = stream
        headers.update({"Content-Type": "application/octet-stream", "Content-Length": str(size)})
    elif body is not None:
        data = json.dumps(body).encode()
        headers["Content-Type"] = "application/json"
    req = urllib.request.Request(API + path, data=data, method=method, headers=headers)
    with urllib.request.urlopen(req, timeout=1800) as r:
        raw = r.read()
        return json.loads(raw) if raw.strip() else {}


def sha256(path):
    h = hashlib.sha256()
    with open(path, "rb") as f:
        for block in iter(lambda: f.read(1 << 20), b""):
            h.update(block)
    return h.hexdigest()


def upload(dataset_id, path):
    name, size, sha = os.path.basename(path), os.path.getsize(path), sha256(path)
    pre = call("POST", f"/datasets/{dataset_id}/upload/presign",
               {"files": [{"filename": name, "sha256_hash": sha, "file_size": size}]})
    if sha in (pre.get("duplicates") or []):
        return "duplicate, skipped"
    u = pre["presigned_urls"][0]
    with open(path, "rb") as f:
        call("PUT", u["upload_url"], stream=f, size=size)
    return call("POST", f"/datasets/{dataset_id}/upload/confirm",
                {"items": [{"object_key": u["object_key"], "sha256_hash": sha, "filename": name, "file_size": size}]})

This sketch has no retries or journal. For real jobs use tools/evren_dataset_upload.py, which adds retry with backoff on 5xx, 429 and network errors, a resumable journal, progress lines and verify.

Verify

After confirming, page through GET /datasets/{id}/items?limit=200 (follow next_cursor until it is empty) and compare the sha256_hash values with your local manifest. Every file should be there with status: ready, and nothing extra. With the bundled tool:

python3 tools/evren_dataset_upload.py verify ./my-dataset
# verify my-dataset: server 9 / manifest 9 | missing [] | extra [] | not ready [] -> OK

Converting .npy to Parquet

The platform rejects .npy, but Parquet is accepted and is a better container for embeddings anyway. This needs pyarrow and numpy (not required by the uploader itself). It assumes a 2-D array (rows, dims) and writes in chunks so large arrays do not have to fit in memory:

import numpy as np
import pyarrow as pa
import pyarrow.parquet as pq

arr = np.load("vectors.npy", mmap_mode="r")          # shape (rows, dims)
writer = None
for start in range(0, len(arr), 100_000):
    chunk = np.ascontiguousarray(arr[start:start + 100_000])
    table = pa.table({
        "id": np.arange(start, start + len(chunk)),
        "vector": pa.FixedSizeListArray.from_arrays(pa.array(chunk.reshape(-1)), chunk.shape[1]),
    })
    writer = writer or pq.ParquetWriter("vectors.parquet", table.schema, compression="zstd")
    writer.write_table(table)
writer.close()

Shard the result if it is larger than about 280 MB.

LLM gateway

This repository is about the Platform REST API for datasets. The LLM gateway is a separate service; this section only orients you.

Base URLhttps://evren-llmapi.ssyz.org.tr/v1
AuthAuthorization: Bearer <evren_llm_ key> (X-API-Key is also accepted)
OpenAPIhttps://evren-llmapi.ssyz.org.tr/openapi.json
Docs UIhttps://evren-llmapi.ssyz.org.tr/docs

Endpoints: chat/completions, completions, messages (Anthropic-style), responses, embeddings, rerank, models, ocr, audio, media, quota, and terms/{status,text,accept}.

Per the platform's pricing page the gateway is free, independent of credits, with limits of 15M tokens per day, 2.5M per 5 minutes and 32 concurrent requests.

Terms must be accepted first

The first call with a new key returns 403 terms_not_accepted until the account accepts the gateway terms:

  1. /v1/terms/status shows whether they are accepted.
  2. GET /v1/terms/text returns the terms. Read them yourself.
  3. POST /v1/terms/accept with {"version": 1} records acceptance.

Accepting terms is a legal act by the account owner. Scripts and coding agents should not do it for you; see Safety rules.

Errors

Shape

Failed Platform API calls normally answer:

{"success": false, "error": {"code": "VALIDATION_ERROR", "message": "...", "details": {}}}

Successful calls usually answer {success, data, message}, though some return the object or list directly. Check the HTTP status first, then read error.code and error.message.

Retrying

  • 5xx, 429 and network failures are worth retrying with exponential backoff. tools/evren_dataset_upload.py waits 5 s, 10 s, 20 s, ... (capped at 120 s) for up to 4 attempts by default.
  • Other 4xx responses are not transient. Fix the request or the key instead of retrying.
  • A repeated upload is safe: the server dedups by SHA-256, and the tool's journal skips files it already finished.

Use it with OpenCode

OpenCode is the first supported agent harness. The repository contains an AGENTS.md contract and a custom command, so an agent can publish a folder for you. Other CLIs (Claude Code, Codex, Gemini CLI, Cursor) are planned; the AGENTS.md contract is plain Markdown, so most of them can already read it.

Dataset publishing with the repo's command

The custom command lives at .opencode/command/evren-publish-dataset.md. OpenCode also reads AGENTS.md automatically as project instructions.

git clone https://github.com/nsozturk/evren-platform-api
cd evren-platform-api
export EVREN_PLATFORM_KEY="evren_plt_..."
opencode

Then, inside OpenCode:

/evren-publish-dataset ./path/to/my-folder

The command walks the agent through: check the folder (data files plus card.json and README.md), warn about .npy and oversized files, preview the request with --dry-run, build the manifest, create a private NLP dataset, upload, verify by SHA-256, and report. It asks before anything public.

To use the command from another project, copy .opencode/command/evren-publish-dataset.md and tools/evren_dataset_upload.py into it (and adjust the script path in the command), or paste GLOBAL_AGENT_RULE.md into your global OpenCode instructions.

EVREN as an OpenCode provider

The LLM gateway speaks the OpenAI-compatible protocol. Add a provider to your opencode.json (this repository ships the same block as opencode.example.json):

{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "evren": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "EVREN",
      "options": {
        "baseURL": "https://evren-llmapi.ssyz.org.tr/v1",
        "apiKey": "{env:EVREN_LLM_API_KEY}"
      },
      "models": {
        "glm-5.3": { "name": "GLM 5.3" },
        "deepseek-v4.1-flash": { "name": "DeepSeek V4.1 Flash" },
        "mimo-v2.6-pro": { "name": "MiMo V2.6 Pro" }
      }
    }
  }
}
export EVREN_LLM_API_KEY="evren_llm_..."    # your own key; never commit it
opencode                                      # then pick evren/glm-5.3 with /models

The key never appears in the file: OpenCode substitutes {env:EVREN_LLM_API_KEY} at load time. The first use of a new LLM key requires accepting the gateway terms, which you do yourself. For a ready-made installer, see the community project bykemalh/evren-llm-opencode.

Safety rules for agents

  • The agent must never print or write EVREN_PLATFORM_KEY.
  • Datasets are created private. Making one public is your decision, made in the web app.
  • Accepting the LLM gateway terms is yours to do, not the agent's.
  • Uploaded datasets may be used by the platform for training under its user agreement; read the agreement before uploading anything you do not want used that way.

FAQ

Can I upload text or tabular data to EVREN?

Yes. Accepted formats include Parquet, Arrow, Feather, SQLite, CSV, TSV, JSON, JSONL, NDJSON, TXT, Markdown and PDF, plus images, audio and video. Create the dataset with "modality": "NLP" and upload the files with the three-step flow in docs/api/upload.md.

Why does the web form not offer NLP?

The web "new dataset" form enables only vision and medical datasets, but the API accepts NLP (verified on 2026-10-26). This project does not know the platform's intent, so treat NLP-through-the-API as working today but not as a promise.

Which API key do I need?

An evren_plt_ key, sent in the X-API-Key header, for anything involving datasets. evren_mdl_ keys are limited to models and inference; evren_llm_ keys only work on the LLM gateway. See the table above.

Is .npy supported?

No. The platform's extension list does not include .npy. Convert arrays to Parquet; docs/api/upload.md has a chunked pyarrow snippet.

How large can a file be?

Files of 0.7 KB, 105 MB and 316 MB all uploaded successfully, and no limit was hit up to 316 MB. The tool warns above 280 MB and the guide recommends sharding to stay within what was tested.

What happens if my upload is interrupted?

Run the same command again. Finished files are skipped from the journal, the server also deduplicates by SHA-256, and verify tells you whether anything is missing.

Does publishing earn credits?

Yes, within the limits in Platform credits: +5 CR per published dataset (up to three a day), plus item milestones, capped at 100 CR of earnings per day.

Is this official?

No. It is an independent community project, not affiliated with or endorsed by SSB or the EVREN platform. See the notice at the top.

Can an AI agent run this safely?

That is what AGENTS.md is for: keys stay in the environment, datasets are created private, terms are never accepted on your behalf, and nothing is made public without you asking.
